# A64 fallback alias performance qualification

Outcome: **REJECT default enablement; retain the emitter and explicit opt-in for
future experiments.** The complete-duration candidate reduced generated bytes
by about 18.6%, but regressed A64 flat-window kernel time by 9.46%, beyond the
registered 5% throughput-loss budget.

This is a new timing result, not a rewrite of the earlier failed exact
95-region static gate. The preregistered mechanism and timing protocol are in
[../2026-10-27-region-alias-performance-plan.md](../2026-10-27-region-alias-performance-plan.md).

## Implementations and workload

- Baseline: `f96fe7a`; fallback multi-entry emitter present, A64 publication
  disabled.
- Candidate: backend code from `6a6c6d7` (test/evidence commit `8ceeee5`),
  with A64 fallback return-site publication enabled.
- Workload: pinned CoreMark `1f483d5b8316753a742cbf5590caf5bd0a4e4777`,
  200,000 iterations and 2K performance seeds. Workload identity:
  `ad43250ce2139ab0d0fdbf1eac0bb1284e00fde62419d387accfe6348cca17aa`.
- Both hosts were independent Release, profile-OFF Emscripten builds. No dump
  or generated-code execution counters were enabled.
- Every native/guest CRC matched. All 60 complete-duration guest samples met
  the ten-second minimum; the shortest was 22.349 seconds.

## Complete-duration result

Five fresh processes per implementation and case, with case rotation and
alternating implementation order. Affinity was `0,2,4,6`; `NODE_OPTIONS` was
empty and no concurrent builds/tests were run. No observations were excluded.

Ratios are candidate/baseline median; lower is better. The unchanged limits
are 1.0526316 for kernel time, 1.15 for Run and compile time, and 1.10 for
emitted bytes.

| Case | Kernel baseline ms | Kernel candidate ms | Kernel ratio | Run ratio | Compile ratio | Bytes ratio | Verdict |
|---|---:|---:|---:|---:|---:|---:|---|
| A32 thunk | 70309.589 | 66680.225 | 0.94838 | 0.94848 | 0.77651 | 1.00000 | pass |
| A32 page-table | 31494.322 | 31164.104 | 0.98951 | 0.98959 | 0.91335 | 1.00000 | pass |
| A32 flat-window | 24818.443 | 24901.311 | 1.00334 | 1.00290 | 0.98677 | 1.00000 | pass |
| A64 thunk | 61754.419 | 63804.775 | 1.03320 | 1.03326 | 0.98021 | 0.81382 | pass |
| A64 page-table | 30046.860 | 31172.892 | 1.03748 | 1.03730 | 0.97026 | 0.81282 | pass |
| A64 flat-window | 22918.225 | 25086.437 | **1.09461** | 1.09404 | 0.94841 | 0.81336 | **FAIL kernel** |

A64 flat-window kernel MAD was 569.218 ms baseline and 638.047 ms candidate.
The five baseline/candidate kernel samples in collection order were:

- baseline: 22.918225, 23.689834, 24.370166, 22.608553, 22.349007 seconds;
- candidate: 25.086437, 25.724484, 25.633386, 23.306489, 23.348351 seconds.

A32 emitted bytes are identical and its publication path is unchanged; its
timing differences are not attributed to the A64-only candidate. A64 compile
and Run limits passed in every case, but those passes do not waive the kernel
failure. Static byte reduction is not called a speedup.

The earlier five-round short screen is retained in `short/`. It was explicitly
not duration-qualified and also failed: A64 flat-window kernel ratio was
1.05910 and A32 page-table compile ratio was 1.24432. The complete-duration
experiment supersedes neither observation nor hides either failure; it provides
the registered qualification result.

## Decision and next experiment

Default A64 alias publication is disabled after this result. The opt-in emitter
and its semantic tests remain available for a separately profiled redesign;
there is no claim that entry selection is yet proven to be the cause. In
particular, V8 13.6 Liftoff lowers `br_table` to a binary compare tree rather
than a real jump table, so a `br_table` rewrite is not assumed to help:
<https://github.com/v8/v8/blob/branch-heads/13.6/src/wasm/baseline/liftoff-compiler.cc#L3268-L3333>.

The next independent optimization experiment is structured-only register-cache
domain pruning. It must leave fallback blocks and any explicitly enabled
aliases unchanged, use emitted-Wasm semantic tests, and pass its own paired
performance qualification.

## Evidence and reproduction

`short/` and `long/` contain every JSON report produced by the two collectors,
compressed individually. `long/commands.json.gz` includes every guest command
and raw output; `before.json.gz` and `after.json.gz` include build, source,
artifact, system, workload and native-oracle provenance. `SHA256SUMS` covers
all compressed reports. From the repository root:

```sh
sha256sum -c internals/measurements/2026-10-27-region-alias-performance/SHA256SUMS
```

The complete-duration collection command was:

```sh
env -u DYN_DUMP_DIR NODE_OPTIONS= taskset -c 0,2,4,6 \
  node internals/measurements/2026-10-23-a64-decoder/duration-paired.mjs \
  /tmp/dynarmic-a64-alias-perf/before-build/examples/browser \
  build-em/examples/browser /tmp/dynarmic-coremark-long \
  /tmp/dynarmic-a64-alias-perf/long-paired 5
```

The collector exited 1 because the preregistered comparator failed, not because
of a crash, CRC mismatch, missing sample or insufficient duration.
